# 시공사례 순서 변경

관리자 목록의 ↑·↓ 버튼을 누르면 바로 저장됩니다. 첫 번째 사례의 위 버튼과 마지막 사례의 아래 버튼은 비활성화됩니다.
분야 필터나 검색 중에는 현재 보이는 두 사례의 전체 목록 위치를 서로 바꿉니다. 숨겨진 사례의 위치는 유지합니다.

새로고침 후에도 순서를 유지하며 홈페이지 `/projects`와 메인 화면 선정 사례에도 상대적인 순서를 반영합니다.
메인 화면의 선정 대상 자체는 기존 구성을 유지합니다. 새 사례는 목록 앞에 추가되고 이후 버튼으로 위치를 바꿀 수 있습니다.

## 저장 방식

- 기존 `sanjung-projects` 테이블에 `id=project-order`, `entityType=project-order`인 별도 항목 하나를 저장합니다.
- 문서에는 `ids` 배열과 순서용 `version`을 저장합니다. 사례 본문이나 사진, 사례 수정 버전은 건드리지 않습니다.
- 기존 GetItem·PutItem·Scan 권한으로 동작합니다. 별도 테이블이나 추가 IAM 설정은 필요 없습니다.
- 관리자 API는 로그인·Origin·요청 크기·중복 ID·현재 목록을 확인합니다. 다른 창에서 먼저 순서를 바꾸면 409를 반환합니다.
- 공개 조회 캐시를 무효화해 다음 방문에서 갱신합니다. 이미 열려 있는 홈페이지는 새로고침해주세요.

## 배포 후 확인

1. 관리자에서 사례를 한 칸 이동하고 새로고침해 위치가 유지되는지 확인합니다.
2. 시크릿 창에서 `/projects` 순서가 동일한지 확인합니다.
3. 냉동공조·섬유덕트 필터와 검색 상태에서도 이동을 확인합니다.
4. 두 관리자 창 중 한쪽에서 이동한 뒤 다른 창에서 이동하면 충돌 안내가 나오는지 확인합니다.
