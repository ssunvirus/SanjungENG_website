# 홈페이지 시공사례 DB 연결

`/projects` 목록과 각 상세 페이지, 사이트맵이 DB 저장 사례를 읽습니다.
기존 정적 사례 8건은 유지하고, 같은 id의 DB 항목이 있으면 DB 내용을 우선합니다.
농협 사례처럼 id와 URL이 다른 경우에도 기존 URL을 유지합니다.
새 사례 주소는 `/projects/{id}`입니다. 메인 화면의 선정 사례 구성은 유지하되 삭제한 사례는 PC·모바일 추천 영역에서도 제외합니다.
PC·모바일 메인 추천도 공개 목록과 같은 제목·간단한 설명·대표 사진·정렬 순서를 사용합니다.
DB로 수정한 사례는 첫 사진을 대표 사진으로 표시하고, 수정하지 않은 사례는 기존 메인 전용 사진을 유지합니다.
새 사례를 메인 추천에 자동 추가하지는 않습니다. 사진이 없는 추천 사례에는 ‘사진 준비 중’을 표시합니다.

## 공개 범위

- 현재 모든 DB 저장 사례는 공개입니다. 임시저장·미리보기·별도 게시 상태는 없습니다.
- 따라서 기존 DB 테스트 글도 이번 코드 배포 후 공개 목록에 나옵니다. 배포 전 실제 내용으로 수정하세요.
- 사진을 업로드만 하면 관리자만 볼 수 있습니다. DB에 저장한 사례가 참조하는 사진만 공개 API로 제공합니다.
- S3 버킷은 계속 비공개로 유지합니다. 추가 IAM 권한이나 퍼블릭 버킷 정책은 필요 없습니다.
- 사진 연결을 제거하고 저장하면 공개 조회에서도 제외됩니다. S3 원본 삭제는 별도입니다.

## 기존 사례와 장애 처리

수정하지 않은 기존 상세 페이지는 원래 화면을 유지합니다.
기존 상세 페이지 8곳은 `LegacyProjectDetail`이 DB 조회와 공통 화면 구성을 담당합니다.
각 경로 파일에는 기존 메타데이터·고유 기본 정보·갤러리를 남기며, 원삼농협의 별도 갤러리 배치도 유지합니다.
DB로 저장한 기존 사례는 `SavedProjectDetail`에서 저장된 글 정보로 표시합니다.
이전 형식으로 대표 사진 한 장만 저장한 기록은 원래 전체 사진을 보완합니다.
새 형식의 사진 목록에서 직접 삭제한 사진은 보완으로 되살리지 않습니다.
기본 사진 구성이 그대로면 기존 갤러리 배치를 유지하고, 추가·제거하여 달라지면 저장된 사진 목록을 사용합니다.
삭제한 사례의 상세 주소는 404로 처리합니다. 삭제 상태를 확인할 수 없는 DB 장애 시 목록과 추천 영역은 비워두고 상세는 오류로 처리합니다. 삭제된 기존 사례를 다시 공개하지 않기 위한 동작입니다. DB 설정이 없는 로컬 환경에서는 기존 정적 사례를 사용합니다.

DB 공개 조회는 60초 캐시를 사용합니다. 관리자 저장 성공 시 캐시를 만료시켜 다음 조회에서 다시 읽습니다.
캐시 만료가 실패해도 이미 성공한 DB 저장을 실패로 보고하지 않습니다.
실패한 DB 조회 결과 자체를 빈 목록으로 캐시하지 않습니다.

## 사진 브라우저 캐시

공개 사진 API의 성공 응답은 `Cache-Control: private, max-age=60, must-revalidate`를 사용합니다.
브라우저가 신선한 캐시를 재사용하는 동안 같은 사진의 서버·S3 요청이 줄어듭니다.
60초가 지나 새로 요청하면 서버에서 DB 공개 연결을 다시 확인합니다. 오류(404·503)는 `no-store`이며,
관리자 사진 API도 기존 `private, no-store`를 유지합니다. 공유 CDN 캐시는 사용하지 않습니다.

사례 삭제나 사진 연결 해제 직전에 받은 사진은 브라우저 캐시 유효기간 동안 최대 60초 재사용될 수 있습니다.
DB 캐시 무효화가 실패하면 기존 DB 캐시의 남은 시간만큼 더 지연될 수 있습니다.
이미 열린 화면에 표시된 사진을 강제로 지우는 기능은 아니므로 화면 반영 확인에는 새로고침이 필요합니다.
이 변경은 HTTP 캐시 지시를 추가하며, S3 파일·사진 주소·버킷 권한은 바꾸지 않습니다.

## 배포 후 확인

1. 테스트 글을 실제 공개할 내용으로 수정하고 저장합니다.
2. 로그아웃 또는 시크릿 창에서 `/projects`를 열어 제목·분야 필터·사진을 확인합니다.
3. 새 사례 상세에 직접 접속하고 새로고침해 제목·위치·내용·사진을 확인합니다.
4. 관리자에서 수정 후 저장하고 일반 창을 새로고침해 반영을 확인합니다.
5. 기존 사례 URL, 없는 상세 URL의 404, `/sitemap.xml`의 새 주소를 확인합니다.
6. 관리자에서 삭제를 취소했을 때 유지되는지, 삭제를 확인했을 때 새로고침 후에도 사라져 있는지 확인합니다. 공개 목록·추천 영역·사이트맵에서 제외되고 상세는 404여야 합니다.

## 삭제 처리

관리자 목록의 수정 버튼 옆에 삭제 버튼이 있습니다. 삭제 전 사례 이름과 원본 사진 삭제 안내를 확인합니다.
기존 사례와 신규 사례 모두 삭제할 수 있습니다. 신규 사례는 사진 정리 후 DB 항목을 완전히 제거하고, 기존 사례는 최소 삭제 표시만 유지합니다. 복원 UI는 없습니다.
삭제 시 공개 캐시를 만료합니다. 이미 열려 있는 페이지에는 새로고침이 필요합니다.
연속 클릭을 차단하고 조건부 쓰기로 다른 창의 변경과 충돌하면 409를 반환합니다. 삭제된 사례는 오래된 수정 요청으로 되살릴 수 없습니다.
기존 public 파일은 유지합니다. 다른 공개 사례에서 사용하지 않는 연결 S3 사진은 삭제합니다. [완전삭제 권한 설정 및 재시도 안내](./permanent-project-deletion.md)를 참고하세요.
