# 견적문의 이메일 연결

## 설정

1. Resend 계정을 만들고 Domains에서 회사가 소유한 도메인을 추가합니다.
2. 도메인의 DNS 관리 화면에 Resend가 안내하는 인증 레코드를 등록합니다.
3. Resend에서 이메일 발송 권한의 API 키를 발급합니다.
4. `web/.env.example`을 `web/.env.local`로 복사하고 아래 값을 채웁니다.

```env
RESEND_API_KEY=발급받은_API_키
ESTIMATE_FROM_EMAIL=산정엔지니어링 <문의발송용주소@인증된도메인>
ESTIMATE_TO_EMAIL=sanjungeng@naver.com
```

발신 주소는 Resend에서 인증한 도메인을 사용합니다. 수신 주소는 네이버 메일을 사용할 수 있습니다. API 키는 채팅이나 Git에 올리지 않습니다. `.env.local`은 Git에서 제외됩니다.

5. 개발 서버를 종료하고 `npm.cmd run dev`로 다시 시작합니다.
6. 테스트용 정보를 입력해 전송하고 수신함과 스팸함을 확인합니다.
7. 배포할 때 호스팅 환경변수에도 동일한 세 값을 등록하고 다시 배포합니다.

## 동작 흐름

`EstimateCta.tsx`가 `FormData`로 입력값을 읽어 JSON으로 바꾼 다음 `fetch('/api/estimate')`로 POST 요청을 보냅니다.

`app/api/estimate/route.ts`의 POST 함수는 업체명, 담당자명, 연락처, 이메일 형식, 문의 분야, 내용 길이, 개인정보 동의를 검사합니다. 통과하면 서버 전용 환경변수를 읽어 Resend API로 메일을 보냅니다. 메일 본문은 일반 텍스트이며 고객 이메일이 있으면 Reply-To로 설정됩니다.

Resend가 메일 발송 요청을 수락한 경우에만 성공 응답을 보냅니다. 이는 수신함 도착을 보장하는 의미는 아닙니다. 폼은 성공 시 초기화되며 실패 시 입력을 유지합니다. 전송 중 버튼을 비활성화하고 중복 클릭을 막습니다.

설정이 없으면 503, 입력 오류는 400, 메일 서비스 오류는 502 응답을 반환합니다. API 키나 서비스의 내부 오류는 고객에게 노출하지 않습니다.

## 현재 범위

문의 데이터는 데이터베이스에 저장하지 않고 이메일로 전송합니다. 실제 운영 공개 전에 봇 차단과 공유 저장소 기반 요청 횟수 제한을 추가해야 합니다. 현재 중복 클릭 방지는 한 브라우저의 진행 중 요청에만 적용됩니다.

참고: https://resend.com/docs/api-reference/emails/send-email
