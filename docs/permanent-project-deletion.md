# 시공사례 완전삭제

목록의 삭제 버튼에서 확인하면 먼저 사례를 비공개로 전환하고, 다른 공개 사례에서 사용하지 않는 연결 사진을 S3에서 삭제합니다.
성공하면 신규 사례의 DynamoDB 항목을 DeleteItem으로 제거합니다.
기존 코드에 있는 사례는 재등장 방지에 필요한 작은 삭제 표시만 남기고 제목·설명·사진 목록은 비웁니다.
기존 public 파일은 Git 배포 자산이므로 서버가 삭제하지 않습니다.

## AWS 권한 추가

IAM → 역할 → `SanjungAmplifyComputeRole` → 권한 추가 → 인라인 정책 생성 → JSON.
정책 이름 예: `SanjungProjectPermanentDelete`. 기존 정책은 유지합니다.

```json
{
  "Version": "2012-10-17",
  "Statement": [
    {
      "Effect": "Allow",
      "Action": "dynamodb:DeleteItem",
      "Resource": "arn:aws:dynamodb:ap-southeast-2:235390156511:table/sanjung-projects"
    },
    {
      "Effect": "Allow",
      "Action": "s3:DeleteObject",
      "Resource": "arn:aws:s3:::sanjung-project-images-235390156511/projects/*"
    }
  ]
}
```

## 배포 후 확인

1. 권한을 추가한 뒤 코드를 배포합니다.
2. 사진이 있는 테스트 사례를 등록합니다.
3. 삭제 확인을 취소하면 그대로 남는지 확인합니다.
4. 삭제를 확인한 뒤 관리자·공개 목록에서 사라지고, S3 객체와 신규 DB 항목도 제거되는지 확인합니다.

## 재시도와 범위

- 사진 삭제나 DB 최종 제거가 실패하면 비공개 상태의 삭제 기록과 사진 목록을 남깁니다. 관리자에 **삭제 파일 정리** 버튼이 표시됩니다.
- 이전 기능으로 삭제했던 사례도 이 버튼으로 정리합니다. 업로드만 하고 저장하지 않은 사진, 과거에 사진 목록에서 제거한 미연결 파일은 추적 정보가 없으므로 이 작업에 포함되지 않습니다.
- 원래 S3 객체가 이미 없어도 삭제 재시도는 안전합니다. 클라이언트가 보낸 사진 경로를 사용하지 않고 서버 DB에서 읽은 사진만 삭제합니다.
- 다른 공개 사례가 참조하는 사진은 유지합니다. 참조 확인과 S3 삭제는 서로 다른 서비스 작업이므로 동시에 API로 같은 사진 경로를 다른 사례에 연결하는 관리 작업은 피합니다.
- S3 버전 관리가 켜져 있으면 DeleteObject는 삭제 마커만 만들 수 있습니다. 기존 버전의 용량은 별도 버전 삭제나 수명 주기 설정이 필요합니다. 안내대로 버전 관리를 비활성화한 버킷을 전제로 합니다.
- 실제 AWS 삭제는 코드 검사에서 실행하지 않습니다. 별도 테스트 사례로 배포 후 확인하세요.
